## 架构

浏览器（HTTPS，同源）→ Nginx `/api/ppe/detect` → 本机回环地址 `127.0.0.1:8766/detect` → 两个私有 YOLO 模型。Nginx 同时提供 `index.html`、CSS、JS、图片。外网只开放 443；8766 不开放。必须限流，且仅给经学校批准的测试教师分发访问码。服务器上禁止把学生原图、模型输出或访问码写入公开目录、Git 仓库或请求日志。

## 在获得学校许可和备案通过后

已准备 `nginx-pilot.conf.example`（草案、未部署、尚未在目标 Nginx 上运行 `nginx -t`）。它按根域名 `https://makerlens-ai.cn` 配置同源页面/API、15MB 上传上限、限流、模型路径隔离、JSON 错误提示及关闭照片请求/响应的代理缓存和缓冲。证书路径仅为占位，不代表已签发；不自动添加 www、不改现有其他站点。启用前必须审查与现有 Nginx 配置是否冲突，并核实证书、DNS、备案和服务允许来源一致。设计依据：[Nginx 代理文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)与[限流文档](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)。

- [ ] 在同学的独立设备与学校网络中验证页面、照片上传、三种检测模式、图片结果和错误提示。
- [ ] 两个同学同时请求时验证繁忙提示与恢复；当前后端只允许单次推理，不能声称支持全班并发。

- [ ] 访问码私下分发，不放入 URL、公开仓库或课堂截图；同学只上传获许可的测试图片。

1. 先确认 CVM 上 Python、CPU、内存、磁盘及网络。当前实例为 2 核、2 GiB、1 Mbps，必须在该实例上用代表性照片测延迟与内存；首轮只允许单张、串行请求。模型文件各约 5.2 MB，但 PyTorch 依赖远大于模型文件。
2. 将受审查的静态资产、`ml/serve.py`、`ml/run.py`、`ml/cloud_serve.py`、私有模型文件传到 CVM。不要上传学生视频、训练数据或测试集。权重仅存于服务器私有目录，不发布到 GitHub 或 EdgeOne 静态资产。
3. 建立 Python 虚拟环境并安装 `ml/requirements.txt` 所列依赖；按 Linux 和 CPU 环境验证版本。用随机生成的长访问码设置环境变量 `MAKERLENS_ACCESS_TOKEN`，不要写入脚本、网页或 shell 历史。使用专用低权限用户运行服务。
4. 以实际 HTTPS 网站地址填写 `--origin`，用私有权重绝对路径填写 `--goggles`、`--gloves`，启动 `ml/cloud_serve.py`。该程序只监听 `127.0.0.1:8766`，不可改为 `0.0.0.0`。用本机 `GET /health` 检查启动状态。
5. Nginx 启用 HTTPS，并把精确路径 `/api/ppe/detect` 代理到 `http://127.0.0.1:8766/detect`。设置 `client_max_body_size 15m`、请求限流、`proxy_read_timeout 200s`；为 API 关闭请求访问日志，不缓存照片和结果。只开放必要端口和指定管理 IP。首页和 API 应保持同一域名，否则会碰到浏览器同源限制。
6. 用新照片测试成功、错误访问码、错误来源、过大文件、断网和模型超时。对不同学生与工位留出独立测试集，记录漏检和误报；教师确认结果后才开展受控试用。

## 当前能力边界

### 教师规则与提示音更新（2026-09-30）

教师可以设置手套“仅观察/要求佩戴/禁止佩戴”、是否要求护目镜及是否启用声音。默认仅观察，不假定所有工序都要求手套。服务端验证并保存规则，每帧返回实际使用的规则及版本，学生不能修改。

浏览器对每个异常类别进行连续3个新鲜样本确认；样本间隔超过5秒、没有目标、规则版本变化或停止监测会重新计数。声音最多每10秒一次，需浏览器允许音频播放；提供测试提示音按钮。完全未检出眼部或手部时显示无法判断，不视为违规或安全。提醒为当前相机单工位的疑似异常，不作身份追踪；多个人先后进入画面可能混淆，须教师核查。

已通过规则单元测试、摄像头流程模拟测试、真实云端规则保存/权限/推理元数据测试，并在网页确认“提示音已启用”。未替用户采集物理摄像头画面，喇叭实际可听性及佩戴识别准确率仍需现场验证。

### 摄像头与教师权限更新（2026-09-30，替代旧手动上传入口）

- “制作与检测”使用摄像头预览和串行连续抽帧：目标最多每秒发起一次，实际间隔含网络及推理耗时；上一个结果返回后才发送下一帧。不录音、不保存监测视频、不把监测帧写进学习档案。
- 推理改为CPU常驻两个模型，保持原有类别、640推理尺寸和0.4置信度阈值。服务器合成帧实测单模型约0.09秒、双模型约0.16秒，这不是浏览器端帧率承诺。
- 未获用户勾选同意不会访问摄像头；先验证试点访问码，再请求摄像头权限。停止、跳到其他页面、进入后台、断网或超时会关闭监测摄像头并隐藏旧结果。模型返回超过10秒不再作为有效当前结果展示。
- 每20分钟学习抓拍保持为独立的本地留档功能。启动监测会停止已开启的学习抓拍，避免争用摄像头；已有档案不会删除。
- 教师管理码与学生访问码分开，私有配置键`MAKERLENS_TEACHER_TOKEN`。教师设置存于`/var/lib/makerlens/ppe-settings.json`；作用范围为当前单一试点课堂，尚非多学校/多班账号系统。
- 学生端只能查看检测项目。服务器忽略包括`/detect`兼容入口在内的客户端模式参数，一律使用教师已保存设置；更改设置需同时通过来源、试点访问码及教师管理码验证。
- `ml/accept_camera.py`已验证教师权限、学生越权拒绝、伪造模式无效及连续帧调用。`ml/test_camera_ui.cjs`用模拟摄像头验证串行发送、停止/后台释放、拒绝权限/断网、许可勾选门槛；未替用户打开物理摄像头，也未采集其周围环境。
- 硬件摄像头、学校网络和真实佩戴准确率仍需现场验收；已知误报问题没有因改为摄像头而消失，不可承担安全保障职责。
